- In Django's ORM tree nodes (like `WhereNode`) and classes heavily reliant on object cloning (like `Query.clone()`), using `__new__` to bypass `.create()` or `__init__` overhead is highly performant. Ensure all internal attributes (e.g., `connector`, `negated`, `children`) are explicitly reassigned correctly, and prefer clean structural list comprehensions over `.append()` loops.
- When writing standalone Django ORM benchmark scripts with dynamic models (e.g., in a `__main__` or `benchmark` app), define the models only *after* calling `django.setup()`. Create their underlying tables using `with connection.schema_editor() as schema_editor: schema_editor.create_model(ModelClass)` to prevent `AppRegistryNotReady` and `OperationalError` exceptions.
